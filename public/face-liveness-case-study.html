Context

Face capture is the gate for identity

The app is a unified enterprise client covering attendance, tasks, approvals, and internal workflows. Face capture has to work in warehouses and yards, under uneven lighting, on mid-range phones, and it cannot accept a printed photo.

I owned the capture pipeline end to end, detection, liveness, spoof resistance, and the UX that actually gets a usable set of images without a trained operator behind the camera.

Problem

Slow, noisy, and blocking the thread that needed to stay free

The first version was slow and noisy. Face detection sat around six seconds. Invalid and spoofed captures were common enough to poison downstream records. Heavy inference on the UI isolate dropped frames during the exact preview the user was trying to hold still for.

A cloud round-trip was the wrong default. Connectivity is unreliable, latency is visible, and identity photos should not need to leave the device to decide "this is a live face."

Investigation

The detector was fine. The spoof model was the bottleneck

Google ML Kit was already the right detector for faces and document edges. The spoof model was heavier than the phones being shipped to, and running it inline with camera frames made the preview stutter.

What was needed: a smaller runtime, a clear split between "is there a face" and "is it live," and a capture state machine that does not depend on a shutter tap from someone wearing gloves.

Options considered

Four paths, one that kept the model's behavior

Rejected
Keep TensorFlow on device
Same graph, same phones. Latency stays at six seconds and the preview keeps stuttering.
Rejected
Move spoof checks to a server
Fails offline, adds visible round-trip latency, and leaks more identity imagery than necessary.
Rejected
Swap in a vendor liveness SDK
Faster to integrate, but it hides the failure modes behind someone else's black box.
Chosen
Convert to ONNX, own the runtime
Keeps the model already trusted, runs it on a runtime built for mobile, and liveness logic stays in our control.

Engineering decision

Convert the graph, keep the model, split the work

TensorFlow converted to ONNX, running through ONNX Runtime on device. ML Kit stays for detection. Liveness (blink, depth-from-video) runs before anything commits. Auto-capture locks a face, waits for liveness, and takes multiple profile stills without a manual shutter.

Pre-process, post-process, and inference all moved onto Dart isolates, so the preview stays a UI problem, not a graph problem. The pipeline got its own architecture and requirements doc, so the next person isn't reverse-engineering a model file.

The ONNX spoof head vetoes prints and screens. A two-blink challenge raises the cost of a replayed video specifically.

04 / CAPTURE

Multiple profile stills captured automatically once every check clears. The person never touches a button.

Implementation

A session is a state machine, not a shutter button

ML Kit proposes the box, the ONNX spoof head vetoes prints and screens, and blink plus depth checks raise the cost of a still-image attack. The UI isolate only renders preview and session state, nothing heavier. Model load and preprocessing were tuned for the hardware actually in the field, not a flagship benchmark device. Failure paths, timeout, failed liveness, low light, retry in-session instead of dumping the user back to a form.

Three layers, not one model doing everything

Result

The camera stopped being the obstacle

Detection-to-capture dropped from around six seconds to around two. Invalid and unusable captures fell roughly 90%. Preview stayed usable through the whole session because the heavy work left the UI thread entirely.

Attendance and onboarding stopped being a fight with the camera. The same pipeline is the reason on-device ML gets treated here as a product surface, not a demo notebook.

Reflection

The conversion mattered more than a new architecture diagram. What was needed wasn't a larger model, it was the model already trusted, on a runtime the phone could finish in time, with liveness that matches the attack actually seen, photos, and UX that doesn't ask a field worker to be a photographer.

Next time: a recorded golden set of spoof and live clips in CI. Latency numbers drift unless the device and the clip are both pinned.
